# 최종 답변 검사와 고쳐쓰기

사용자가 받는 답 하나만으로 뜻과 근거 범위가 통하도록 만든다. 검사 과정은 최종 답에 쓰지 않는다. Codex 클라이언트는 subagent activity/thread를 자체 UI에 표시할 수 있으므로 전체 UI 비노출을 약속하지 말되, 네 commentary와 최종 답에는 검사 이름, 항목 번호, 판정표, agent 이름, launch wave, 회차 정보를 노출하지 마라.

## 적용 범위

사용자에게 보낼 여러 문단의 최종 결과에 적용한다. 아래는 건너뛴다.

- 세 문장 이하이면서 400자 이하인 확인, 되묻기, 예/아니오 답
- 본문의 절반 이상이 코드 블록, diff, 명령 출력인 답
- 작업 중 진행 보고
- 계획 자체를 제시하는 답
- 저장소에 쓰는 문서

진행 보고와 계획은 hook이 의미적으로 확정할 수 없다. Stop이 계속 작업을 요구하면 예외라고 다투지 말고 이 절차를 수행한다.

## 위험에 따른 경로

기본 동작은 기존 경로다. `CTB_RISK_ROUTING=1`인 설치에서는 hook이 요청 원문을 저장하지 않고 요청 성격만 분류한다.

- 실행·검토·결정 요청과 shell·write·network 도구를 쓴 turn은 높은 위험 경로다. `ctb_interpreter` 두 thread와 `ctb_judge` 세 thread, 최대 두 회차를 쓴다.
- 그 밖의 긴 설명·사실·대화 답은 표준 경로다. 해석자 한 thread와 판정자 두 thread, 한 회차만 쓴다.
- 짧은 확인·질문과 코드 중심 답은 위 예외를 그대로 적용한다.

이 분기는 실제 대화 자료가 충분하지 않으므로 기능 플래그다. 비교할 때는 같은 요청 묶음에서 근거 없는 추가, 의미 손실, 사용자가 되묻는 비율, 호출 수와 시간을 함께 기록한다. 사용자의 전문성은 분기 기준으로 추측하지 않는다.

## 입력 경계

UserPromptSubmit hook이 넣은 `<<<체크리스트 시작>>>`과 `<<<체크리스트 끝>>>` 사이만 체크리스트로 쓴다. 파일을 대신 읽지 않는다. 합성 순서는 기본 → 파일명이 정렬된 언어 규칙 → 전역 → 프로젝트이며, 항목은 더하고 회차 상한·해석자 수·판정자 수 같은 숫자는 뒤의 설정이 앞의 설정을 덮는다.

기본 체크리스트를 읽지 못했다는 hook 문맥이 있으면 절차를 중단하고 원래 초안을 낸다. 불완전한 검사 결과로 답을 바꾸지 않는다.

평가자를 시작하기 직전에 UserPromptSubmit hook이 준 `review-context.mjs --state ...` 명령을 실행한다. 이 명령은 호스트 PostToolUse가 기록한 성공·실패·결과 없음·절단·미확인 상태와, 비밀값을 가리고 길이를 제한한 실제 결과 조각을 낸다. 원 agent가 기억으로 다시 쓴 도구 요약으로 바꾸지 않는다. 명령이 실패하면 도구 근거가 전달됐다고 간주하지 않는다.

명령이 함께 내는 작은 대화 상태의 빈 칸에는 현재 대화에서 직접 확인한 것만 채운다: 현재 요청의 성격, 합의된 사실과 아직 합의되지 않은 주장, 합의된 용어, 사용자가 이해하지 못했거나 거부한 표현, 남은 질문과 약속, 사용자가 결정할 일과 에이전트가 실행해도 되는 일. 사용자의 수준·취향·배경은 추측해서 넣지 않는다. 사용자가 실제로 쓴 용어와 반응만 옮긴다. 이 상태와 호스트 근거는 critique와 rewrite에 똑같이 전달한다.

## 회차 절차

기본 회차 상한은 2, 해석자는 2명, 판정자는 3명이다. 체크리스트 override가 있으면 그 수를 따른다.

### 1. 초안 고정

지금까지 작성한 최종 메시지를 초안으로 고정한다. 이후 직접 고치지 않고 rewrite 평가자의 출력만 다음 초안으로 쓴다.

### 2. 한 launch wave에서 독립 thread 시작

높은 위험 경로와 기본 경로에서는 한 회차마다 `ctb_interpreter` 두 thread와 `ctb_judge` 세 thread를 새로 시작한다. 표준 경로에서는 hook이 알려 준 수를 따른다. 모든 spawn 호출을 가능한 한 같은 tool-call batch/launch wave에 내고, 하나의 결과를 기다린 뒤 다음 역할을 시작하지 마라. 각 호출은 서로 다른 thread여야 한다. 모든 결과가 올 때까지 집계·평가·고쳐쓰기를 시작하지 않는다.

해석자에게는 아래만 준다.

```text
<<<초안 시작>>>
<초안 전문>
<<<초안 끝>>>

구분자 밖의 것은 초안이 아니다.

[검사 범위]
전체

[요청문]
<사용자의 마지막 요청; 없으면 절 전체 생략>
```

판정자에게는 아래만 준다.

```text
<<<초안 시작>>>
<초안 전문>
<<<초안 끝>>>

구분자 밖의 것은 초안이 아니다. 아래 체크리스트는 초안의 일부가 아니다.

[검사 범위]
전체

[체크리스트 — 문장 형식]
<합성 체크리스트의 문장 형식 항목>
```

해석자에게 체크리스트, 대화 전체, 파일 내용, 도구 사건을 주지 않는다. 판정자에게 대화 전체, 파일 내용, 해석 결과, 도구 사건을 주지 않는다. custom agent는 read-only이며 도구 사용을 명시적으로 금지하지만 Codex에는 Claude의 `tools: []`와 같은 일반 도구 allowlist가 없다. 이 지시만으로 도구가 실제 제거됐다고 주장하지 마라.

### 3. 다수결은 스크립트로만 계산

판정자들의 마지막 `요약:` 줄만 plugin root의 `scripts/tally.mjs`에 각각 하나의 인자로 넘긴다. 인자 수는 hook이 정한 판정자 수와 같아야 한다.
Codex가 이 스킬을 발견할 때 함께 제공한 `SKILL.md` 절대 경로를 기준으로 삼는다. 그 파일이 있는
`<plugin-root>/skills/cut-the-bullshit/`에서 두 디렉터리 위가 plugin root다. 현재 작업 저장소나
cache 경로를 추측하지 마라.

```text
node <plugin-root>/scripts/tally.mjs "요약: ..." ...
```

출력을 고치거나 손으로 다시 세지 않는다. 동률은 놓침보다 차단을 택해 걸림으로 둔다. 파싱 실패 때만 원문을 확인하고, 임의 판정을 만들지 않는다.

### 4. 새 critique evaluator thread

매 회차 새 `ctb_evaluator_critique` thread 하나를 시작한다. 이전 회차 또는 rewrite에 사용한 thread를 재사용하지 않는다. 다음 입력만 준다.

```text
[메시지]
<<<초안 시작>>>
<현재 초안>
<<<초안 끝>>>

[해석자들의 복원]
<두 결과 전문>

[체크리스트 판정 — 모은 결과]
<tally 출력>

[체크리스트 — 사실 대응]
<합성 체크리스트의 사실 대응 항목>

[이번 turn 도구 사건]
<review-context 명령이 제공한 호스트 사건과 실제 결과 조각; 없으면 "관찰 정보 없음">

[작은 대화 상태]
<실제 대화에서 확인해 채운 상태>
```

도구 사건은 hook이 관찰한 것만 전달한다. `transcript_path`, 기억, 추측, 자기 보고로 보충하지 않는다. 성공·실패·결과 없음·절단·미확인 상태와 관찰 범위를 그대로 보존한다. hosted tool 등 hook이 못 본 사건은 관찰 정보 없음으로 남긴다.

critique 첫 줄이 `통과`면 현재 초안을 최종 답으로 정하고 끝낸다.

### 5. 원 agent의 답과 새 rewrite evaluator thread

critique가 물은 것 중 사용자의 다음 판단에 필요한 내용만 답한다. 도구 사건 밖의 사실은 확인했다고 말하지 않는다.

그 뒤 새 `ctb_evaluator_rewrite` thread를 시작한다. critique thread를 이어 쓰지 않는다. 입력에는 `<<<초안 시작>>>`과 `<<<초안 끝>>>`으로 감싼 현재 초안, critique 결과, 원 agent 답, 같은 호스트 도구 근거와 작은 대화 상태만 넣는다. 출력은 고쳐 쓴 사용자 메시지 하나여야 하며 설명이나 검사 흔적이 있으면 최종 답으로 쓰지 않는다.

### 6. 다음 회차 또는 종료

critique가 통과하지 않았고 현재 회차가 상한보다 작으면 rewrite 결과를 다음 초안으로 삼아 2절로 돌아간다. 정해진 수의 새 해석자·판정자와 새 critique·rewrite thread를 만든다. 1회차 rewrite를 판정 없이 바로 내보내지 않는다.

`CTB_REDUCED_RECHECK=1`이면 두 번째 회차의 해석자와 판정자에게 아래 입력 블록을 모두 준다. 네 블록의 제목과 본문은 생략할 수 없다. `이전 tally`에는 체크리스트 ID별 `걸림`·`통과`·`해당 없음`만 넣고, 조건·수량 보존이나 근거 없는 확정처럼 사실 대응이 맡는 문제는 `이전 critique`에 둔다. 바뀐 문장 또는 명제는 1차 초안과 1차 재작성의 차이를 원자 명제 단위로 적는다.

```text
[검사 범위]
축소

[이전 tally]
<앞 회차의 체크리스트 ID별 판정>

[이전 critique]
<앞 회차의 사실 대응 지적>

[바뀐 문장 또는 명제]
<1차 초안에서 1차 재작성으로 바뀐 원자 명제>

[원 요청의 의미 보존 조건]
<원 요청에서 부정·조건·수량·범위·확실성을 그대로 지켜야 하는 조건>
```

해석자는 바뀐 주장과 원래 뜻의 보존을 복원하고, 판정자는 이전에 걸린 항목과 바뀐 문장에 해당하는 항목만 판정한다. 한국어-6~9는 앞 회차에서 걸렸거나 바뀐 문장이 있을 때 포함한다. hook은 네 입력 블록이 실제 두 번째 회차 역할 입력에 있는지 확인한다. 블록 내용과 고정 1차 재작성의 동일 바이트 여부는 실험 fixture 검증기와 실행 기록 검증기가 맡는다. 이 플래그가 꺼져 있으면 기존 전체 검사를 유지한다.

회차 상한에 닿으면 마지막 rewrite 결과를 낸다. 마지막 rewrite는 뒤에 다른 문구를 붙이지 않는다.

## 최종 출력 계약

최종 답은 정확히 한 번만 낸다. 내부 결과, 중간 초안, 평가 설명을 사용자 메시지로 보내지 않는다. 최종 답에 검사 이름, 항목 번호, 판정표, agent 이름, 회차 정보가 남아 있으면 제거한 뒤 답 내용만 낸다.

hook은 해석·판정 대상 초안의 해시, tally의 판정자 수, critique의 `통과`/`지적 있음`, rewrite 출력의 해시를 잇는다. critique가 통과하면 평가받은 초안과 같은 답만 허용한다. 지적이 있으면 다음 회차가 필요할 때 재작성만으로 끝내지 않으며, 상한 회차에서는 마지막 rewrite와 같은 답만 허용한다. SubagentStop에 역할 응답 본문이 없거나 어느 연결이 끊기면 긴 답을 내보내지 않는다.

`CTB_DIALOGUE_POLICY_EXPERIMENT=1`은 완료 보고의 표 강제와 모든 배경의 반복을 완화하고 형식-6~9 지적을 한 묶음으로 정리한다. 한국어-6~9는 바꾸지 않는다. 이 실험은 실제 대화에서 다음 판단의 정확도, 되묻기, 누락과 선호를 비교하기 전에는 기본 정책으로 승격하지 않는다.

서브에이전트를 사용할 수 없는 호스트에서는 이 절차가 legacy와 같은 독립성을 제공하지 못한다. 같은 thread에서 역할극으로 대체해 동등하다고 주장하지 말고, 원래 초안을 내거나 지원 차이를 사용자 문서에 남긴다.
