# 기본 체크리스트

메시지마다 기준이 달라지지 않는 닫힌 목록이다. 자립성 판정이 못 잡는 것을 여기서 잡는다.

항목은 두 종류다. 문장 형식은 메시지만 보아도 판정되므로 판정자가 본다.
사실 대응은 원 에이전트에게 물어야 판정되므로 평가자가 본다.

언어 규칙은 언어별 파일에 있다. 한국어는 `ko.md`.

## 문장 형식 — 판정자가 판정한다

| ID | 묻는 것 | 걸리는 경우 |
| --- | --- | --- |
| 형식-1 | 이 메시지 안에서 뜻을 밝히지 않은 말을 이미 아는 말인 것처럼 썼는가 | 처음 나오는 이름·약어·개념을 설명 없이 쓴다 |
| 형식-2 | 개념을 사물이나 사람에 빗대었는가 | 빗댄 표현이 있고, 본래 의미로 쓴 문장이 따로 없다. 그 언어에서 이미 본래 뜻으로 굳은 관용 표현은 걸지 않는다 |
| 형식-3 | 뒤에서 뜻이 밝혀지는 말을 앞에서 썼는가 | 앞 문단을 읽는 데 뒤 문단이 필요하다 |
| 형식-4 | 이 메시지 밖을 찾아가야 **뜻이 통하는** 곳이 있는가 | 파일·대화·앞선 회차를 보라고 넘긴다. 사용자가 결과를 **검증**하려면 코드를 봐야 한다는 것은 여기에 걸지 않는다 |
| 형식-5 | 각 문단을 지웠을 때 답·사실·근거·추론·반론·결정 가운데 사라지는 것이 있는가 | 지워도 아무것도 사라지지 않는 문단이 있다 |
| 형식-6 | 싸구려 상투구를 썼는가 | 어디에 넣어도 뜻이 같은 문구가 있다 |
| 형식-7 | 감상적인 수사를 썼는가 | 사실을 전하지 않고 느낌만 전하는 문장이 있다 |
| 형식-8 | 발표자료 장표 같은 문구를 썼는가 | 표제어만 늘어놓고 무엇을 했는지 말하지 않는다 |
| 형식-9 | 과도하게 힘있는 문장을 썼는가 | 강조가 많아 무엇이 중요한지 가려진다 |
| 형식-10 | 깨진 문자나 이 맥락에 없는 낱말을 내보냈는가 | 인코딩이 깨진 글자, 다른 언어의 낱말이 이유 없이 섞인다 |
| 형식-11 | 완료 보고인데 결론 한 줄 → 완료한 것 → 잔존 문제 순의 표가 아닌가 | 완료 보고를 산문으로 썼다 |
| 형식-12 | 이 메시지가 검사를 받았다는 것을 **드러내는** 문장이 들어 있는가 | "검토 결과", "N회차", "체크리스트" 같은 말이 사용자에게 나간다. 검사 이야기가 **없는** 것은 통과다 |

형식-5는 문단을 실제로 지워 보고 판정한다. 지웠을 때 사라지는 것이 없으면 걸림이다.

형식-6부터 형식-9까지는 빼는 대상이 정보가 아니라 정보를 담지 않은 문장이라는 점이 같다.
정보와 맥락은 빼지 않는다. 빼면 압축이지 정리가 아니다.

### 정도를 묻는 항목은 한 번의 판정으로 믿지 않는다

형식-1·2·4·6·8은 따올 말이 있는지가 아니라 정도가 그러한지를 묻는다. 2026-08-26 측정에서
같은 초안·같은 모델로 여섯 번 돌렸을 때 실행마다 갈린 것이 이 항목들이다.

이 항목은 판정자 여럿의 다수로 정한다. 만장일치인 항목은 그대로 확정한다.
판정자가 해석자보다 강한 모델을 쓰는 것도 같은 측정에서 나왔다. 약한 모델은 이 항목들을
틀린다.

## 사실 대응 — 평가자가 판정한다

| ID | 묻는 것 | 걸리는 경우 |
| --- | --- | --- |
| 사실-1 | 확인하지 못한 것을 확인했다고 썼는가 | 돌려보지 않은 것을 "동작한다"고 쓴다 |
| 사실-2 | 사용자가 다음 판단을 내리는 데 필요한 것 가운데 빠진 것이 있는가 | 평가자가 물었을 때 원 에이전트가 답할 수 있다 |

사실-2의 대상은 에이전트가 한 일 전부가 아니라 사용자가 다음 판단을 내리는 데 필요한
것 전부다. 이 경계가 없으면 메시지가 작업 기록의 사본이 된다.
